# ShadcnStore dashboard and landing reference

The current interface adapts the MIT-licensed ShadcnStore dashboard and landing template: https://github.com/shadcnstore/shadcn-dashboard-landing-template. Source commit and file provenance are recorded in `shadcnstore-reference.json`. The requested 21st.dev CLI command returned `Template not found`; the corresponding public source was cloned into the ignored reference directory instead. The CLI did not install this template successfully.

The app uses the template's dark neutral tokens: background oklch(.145 0 0), card oklch(.205 0 0), primary oklch(.922 0 0), white text, muted neutral text and translucent neutral borders. Blue, green and amber are chart/status colors. Local Inter Variable replaces Geist, with its OFL license included. The Shortlist logo, home, authentication and all recruiter/client screens use this palette. The homepage and authentication pages retain the original Mosaic layout and animated background. The original tile, diagonal-light and wave phases use muted blue, teal and violet on the homepage, balanced with the dashboard's charcoal base and white actions. Authentication keeps neutral grayscale. Pixel headings and the large footer wordmark are restored on the homepage. `home-mosaic.css` scopes the saved public design to marketing/authentication roots so the dashboard remains unchanged.

`src/components/ui/Card.jsx` adapts the source Card slots to JavaScript and the existing stylesheet. `src/template-theme.css` supplies equivalent Card layout, template tokens, sidebar, forms and responsive styles. The app keeps its existing Next.js/Node stack and native form/dialog controls, without importing the template's unrelated mail, commerce, chat, billing or demo API modules. No package was added.

The recruiter and client dashboards follow the template's metric-card and two-panel analytics layout. Charts use actual role-scoped `/api/jobs` counts. Recruiter applications are partitioned into not submitted, with clients, and joined; client totals use only submitted applications. A candidate applying to two roles counts twice. The display is a current snapshot and does not invent historical trends or revenue. Requisition bars open the matching ranking or client shortlist. Empty workspaces display zero counts and an empty state.

Readable text remains global: 16px body text and at least 14px explicit supporting text. Forms and charts stack on phones. Navigation retains its keyboard-aware mobile drawer. The marketing navigation uses a local blurred panel behind its links, rather than a full-width blurred header. Home project search remains a native GET form with `q`, without a search backend.

The original hiring safeguards remain in the Node backend: server-side role checks, client-scoped candidates, masked identities, evidence validation, consent, recruiter CV review, deletion and audit. Screens retain live application APIs rather than the reference's mock business data.
